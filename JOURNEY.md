# UniThrift — Integration Journey & Troubleshooting History

This log documents the process, technical issues, attempted solutions, failed paths, and final working strategies encountered during the integration of the **Stitch MCP Design System** into the local **UniThrift** project.

---

## ⚡ Issue 1: PowerShell Script Execution Policies

### Problem
When starting the local web server using `npx -y http-server -p 8080`, PowerShell raised a security error:
> `npx : File C:\Program Files\nodejs\npx.ps1 cannot be loaded because running scripts is disabled on this system.`

This occurs because PowerShell's execution policy restricts running unsigned `.ps1` script wrappers generated by npm/npx installations.

### Things Tried & Failed
* **Direct Execution:** Running standard npm/npx server commands directly from the terminal without special execution parameters failed immediately due to the environment's security policies.

### What Worked
* **Python Server Handoff:** Since Python utilizes standard platform binaries (`python.exe` and built-in standard libraries) instead of scripting wrapper scripts, running:
  ```powershell
  python -m http.server 8765
  ```
  bypassed the PowerShell execution policy check entirely. It created a highly reliable, zero-dependency local static web server.

## 🎨 Issue 2: Transitioning to the Exact Stitch Design

### Problem
The initial approach attempted to map the Stitch design system tokens (colors, fonts, radius) onto our existing custom Vanilla CSS architecture. However, this failed to achieve a pixel-perfect replica of the Stitch design, and the user requested the *exact* UI (including the logo and precise layout generated by Stitch).

### Things Tried & Failed
* **CSS Variable Mapping:** Trying to manually rebuild the Tailwind layout using custom CSS variables (`--surface`, `--primary`) was too complex, resulted in structural mismatches, and missed the precise utility combinations Stitch generated.

### What Worked
* **Direct HTML & Tailwind Import:** We completely deleted `styles.css` and `app.js`. Instead, we extracted the raw, exact HTML generated by the Stitch MCP (including the inline `<script id="tailwind-config">`) and saved them directly into our local workspace.
* **Component Fidelity:** This ensured that every single element—from the real Google Cloud-hosted logo and AI-generated product images, down to the exact `box-shadow` and `border-radius` utilities—was a 1:1 pixel-perfect match.

## 🔄 Issue 3: Managing Multiple Screens

### Problem
The Stitch design consists of multiple separate screens (Splash, Dashboard, Marketplace, Flatmates, PGs, Profile, Item Details). Our original architecture was a Single Page Application (SPA) driven by `app.js` with dynamic section swapping.

### Things Tried & Failed
* **SPA Injection:** Trying to dynamically inject raw Stitch HTML strings with inline `<script>` tags into a single `<div id="app">` caused issues, as the browser does not execute `<script>` tags injected via `innerHTML`, breaking interactive elements like the Flatmate swipe cards.

### What Worked
* **Multi-Page Architecture:** We embraced a traditional multi-page setup. We created separate HTML files for each screen:
  - `splash.html`
  - `index.html` (Dashboard)
  - `marketplace.html`
  - `flatmates.html`
  - `pghostels.html`
  - `item.html`
  - `profile.html`
* **Navigation Linking:** We modified the `href` attributes in the bottom navigation bars of every file using string replacement, allowing seamless navigation between the static files exactly as Stitch intended.

## 🐛 Issue 4: Splash Screen "Stuck" State

### Problem
The `splash.html` screen provided by Stitch was purely visual (an animated logo and loading dots) but lacked any buttons or JavaScript logic to navigate to the main application, leaving the user "stuck".

### What Worked
* **Custom JS Injection:** We injected a custom `DOMContentLoaded` event listener into `splash.html` that automatically redirects the user to `index.html` after 3 seconds, mimicking native app behavior. We also added a full-body click listener to allow users to skip the animation instantly.

## 🔣 Issue 5: Text Encoding Glitches

### Problem
When downloading HTML directly from the `Invoke-RestMethod` and saving via `Set-Content` in PowerShell, some UTF-8 characters (like the `⭐` star and `•` bullet point) were converted into ANSI mojibake (e.g., `â­ `).

### What Worked
* **Explicit UTF-8 Overrides:** We explicitly set `-Encoding UTF8` on the PowerShell read/write commands, and used precise `.Replace()` string methods to overwrite the corrupted characters back into their proper Unicode format.
